# CAN Bus Telemetry & Diagnostics Simulator (C)

A lightweight, modular C-based simulation of an automotive CAN bus network and diagnostic processor. This project models how distributed control units (ECUs, BCMs, ABS modules) exchange data through packed bitfields and byte frames, demonstrating low-level systems programming in pure C.

---

## Problem & Real-World Context

In modern automotive and industrial embedded systems, multiple Electronic Control Units (ECUs) share a single **CAN (Controller Area Network) bus** to communicate critical telemetry data. Because bandwidth and memory are strictly limited, data is packed tightly into binary bitmasks and byte frames. 

Processing this stream reliably on resource-constrained hardware requires:
* **Precise bitwise manipulation** to decode raw status flags.
* **Robust dynamic memory management** (heap allocation and safe buffer resizing) when message counts are unpredictable.
* **Modular architecture** separating data generation from diagnostic processing.

This project bridges software logic and embedded protocols by simulating the entire pipeline from message transmission to human-readable diagnostic logging.

---

## Project Architecture & Workflow

The system is divided into two independent, collaborating programs:

### 1. CAN Generator (`can_generator.c`)
* Simulates physical automotive modules transmitting messages over the bus:
  * **Engine ECU (`0x100`)**: Temperature, approximate RPM calculation, oil pressure.
  * **Body Control Module - BCM (`0x200`)**: Door and trunk status.
  * **Brake System (`0x300`)**: ABS status, brake pad wear, electronic stability control, and individual tire sensors.
* Packs randomized sensor states into 8-bit registers using bitwise shifts and masks, saving each message into individual frame files (`input_data/data_X`).
* Allocates dynamic arrays of `CAN_Frame` structures on the heap.

### 2. CAN Processor (`can_processor.c`)
* Scans and reads incoming telemetry frames from the input directory.
* Implements **dynamic heap buffering** with safe `realloc` growth to handle an arbitrary number of incoming messages without memory leaks.
* Performs **bit-level decoding** to translate raw binary masks into clear, structured diagnostic metrics.
* Outputs a consolidated diagnostic report to `output_data.txt`.

---

## Technical Highlights & C Concepts Used

* **Custom Structures (`struct`)**: Encapsulates CAN frame metadata (`id`, `length`, `data`) for clean, object-like data organization in C.
* **Dynamic Memory Management**: Utilizes `malloc`, safe `realloc` buffer expansion, and proper `free` cleanup to prevent memory fragmentation and leaks.
* **Bitwise Operations**: Uses bit-shifting (`>>`) and bitmasking (`& 1`) to extract individual hardware flags from raw bytes.
* **File I/O & Parsing**: Automated reading/writing of structured text files simulating serial communication logs.

---

## File Structure

* `can_generator.c` — Source code for generating raw CAN bus frames and structuring them into heap-allocated frames.
* `can_processor.c` — Diagnostic processor managing heap buffers, parsing bit fields based on CAN IDs, and writing diagnostic reports.
* `input_data/` — Directory containing generated raw frame files (`data_0`, `data_1`, etc.).
* `output_data.txt` — Final structured diagnostic summary report generated by the processor.
